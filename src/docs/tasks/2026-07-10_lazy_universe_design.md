# 지연 우주(Lazy Universe) 재설계 — 실측 기록 + 설계 (2026-07-10)

상태: **설계 승인 대기.** 실측 완료(본 문서), 구현 미착수.
선행 완료: VarEq 에러코드 대조 패치(71d9345) — 에러 셀 캐시 전멸 해소(본 문서 §1.3).

실측 도구: `modBenchReal.bas`(커밋됨). 실데이터 fixture는 "지출 리팩토링" 워크북에서
열만 격리 복제(`ExtractFixture` -> `%TEMP%\uf_bench_fixture.xlsx`, 원본 무접촉).
대표 열: DW_P(금액 `#,##0`, 91,235행/고유 47,397 — 이하 "고카디널"), DW_Z(카운트,
고유 15), DW_D(텍스트 General, 고유 225), SL_V(`@` 텍스트 28k행/고유 20k) 등.

## 0. 설계 원칙 (상위 규칙, 지문 설계와 동일)

**속도는 측정·알고리즘으로 얻는다. 정합성과 트레이드오프하지 않는다.**
이 재설계의 모든 결정은 아래 실측이 근거이며, 정합성 갭을 여는 항목은 전부
실측(P10 프로브, 전수 동치 테스트)으로 닫은 뒤에만 채택한다.

## 1. 배경 실측 — 체감 저하의 3중 원인

사용자 증상: "검색 오버헤드가 대규모 리팩토링 전보다 악화, '즉시'가 아니다."

### 1.1 콜드 스캔 940ms (회귀의 본체)

셀 1개 퀵필터 e2e(fixture, OptimizedMode): 웜은 전 열 55~94ms로 양호하나
**고카디널 열의 세션 첫 필터만 ~1,006ms**. 콜드 스캔 940ms의 단계 분해:

| 단계 | n | ms | 비고 |
|---|--:|--:|---|
| Value2 벌크 | 91,235 | ~5 | |
| pass1 dedup (타입태그 문자열 + dict) | 47,397 | 184 | |
| pass2 렌더 `.Text` 고유값당 COM | 47,397 | **406** | WText로 바꾸면 180 |
| accumulate (rowByKey vbTextCompare + AppendVm) | 47,397 | 248 | |
| displays clsSet.LoadFromArray | 47,397 | 68 | |

**원인 커밋은 백지 재설계 Stage 2/3(e725b3f/415031f)의 우주 렌더 도입.**
구 엔진(b403593)은 `rTarget.Value` 벌크 1회 + 인메모리 집합 적재뿐(렌더 제로)이라
콜드가 수십 ms — 대신 표시를 예측해서 정합성 결함(재설계의 이유)을 안고 있었다.
롤백은 답이 아니고, 관측을 싸게 만드는 것이 답이다.

또한 기존 합성 벤치는 `(i Mod 5000)` 저카디널 가정("실사용 필터 열은 저카디널")이
박혀 있어 미스를 ~7배 과소평가했다(합성 100k=137ms vs 실측 91k=940ms).
**실데이터 금액/코드 열은 거의 전행 고유** — 가정이 실데이터에서 깨졌다.

### 1.2 제외 모드 4초 (스캔 무관의 별개 지뢰)

여집합 47,396항목 xlFilterValues 적용 = **4,045ms** (제외 e2e 콜드 5.1s/웜 4.4s).
실측 원장의 "배열 20k/39ms 사실상 무제한"이 47k에선 성립하지 않는다(85us/항목,
비선형). 우주를 어떻게 스캔하든 이 apply 비용은 남는다 — 적용 전략 자체의 문제.

### 1.3 에러 셀 캐시 전멸 (완료 — 71d9345)

VarEq가 에러 Variant를 무조건 불일치 처리 -> 열에 #N/A/#REF! 1개면 매 접근 전량
재스캔. 실데이터는 에러 상존이라 "매 검색이 콜드"가 됐었다(애드인 체감의 주범).
에러코드 대조로 수정, 실측 125ms(영구 재스캔) -> 17.6ms(적중). dist .xlam 환경에서도
HIT 검증(BenchAddinCacheHit: 콜드 174 -> 웜 56.6/56.6).

## 2. 핵심 실측 — 재설계를 가능케 하는 사실

### 2.1 벌크 렌더: Evaluate(TEXT) COM 1회

`ws.Evaluate("TEXT(범위,서식)")`이 91,235행을 **1회 호출 113ms**로 렌더(배열 반환).
- 정합: 고유값 47,397 전수 + General(189) + 빈칸 2만 열에서 현행 엔진 산출물
  (우주+행수지도)과 **완전 동치, 불일치 0**.
- WText(=TEXT 함수) 단독 오라클도 전수 0 불일치 (uniq 47,397, `#,##0`/General).
- **함정(실측)**: `TEXT(빈칸)="0"` — v2 IsEmpty 가드로 빈칸을 렌더값과 무관하게
  건너뛰어야 한다. 에러셀은 에러가 전파되어 배열 원소가 Error — 셀별 `.Text` 폴백.

### 2.2 멤버십은 dict 없이 싸다

렌더 배열 직스캔(91,235행): 토큰 1개 StrComp **9.8ms**(+빈칸/행수 계수 공짜),
토큰 20개(소형 dict) 54.7ms, 값 브리지(파싱값 WText 1회 -> 스캔) 11.7ms.
부분일치 InStr 직스캔 39.1ms. **지연 uniq dict 구축(제외가 요구할 때 1회) 179.7ms.**

### 2.3 dict의 소비자 분석

| 자료구조 | 소비자 | 홧 경로(퀵/포함 완전일치)에 필요? |
|---|---|---|
| Displays(clsSet 우주) | 제외(universe-matched), 부분일치 | 불요 — 멤버십 스캔으로 대체 |
| ValueMap | 값 브리지 | 불요 — 파싱값 WText 1회 + 멤버십 |
| RowCountByKey | 자가검증 ExpectedRows뿐 | 불요 — 멤버십 스캔이 계수 반환 |

## 3. 설계

### 3.1 지배 원리 (재정식화)

```
우주      = 관측된 렌더 배열 (블록별 Evaluate(TEXT) 1회, 빈칸/에러 가드)
집합/지도 = 우주가 아니라 우주에 대한 '인덱스'.
            그것을 요구하는 소비자(제외/부분일치)가 처음 나타날 때 지연 구축,
            자산에 캐시. 홧 경로는 인덱스 없이 배열 직스캔.
matched   = 표시레인(토큰 멤버십 스캔) UNION 값레인(파싱값 -> 블록서식 WText -> 멤버십)
적용      = xlFilterValues(matched)                       [포함]
          = "<>" 스칼라 (토큰<=2) / xlFilterValues(여집합) [제외, P10 게이트]
계수      = 멤버십 스캔의 부산물 (자가검증 ExpectedRows, BlankCount)
```

### 3.2 자산 구조 변화

- clsColAsset: `RenderedVec`(블록 렌더 완료된 표시키 배열, 행 정렬) 신설.
  `Displays`/`ValueMap`/`RowCountByKey`는 **지연 프로퍼티**로 강등(최초 접근 시
  RenderedVec에서 1회 구축 후 보관, 고카디널 ~180ms).
- 지문 계약(clsColSig/GetColumnAsset/Matches) 무변경. 캐시 적중 경로 무변경.
- 메모리: RenderedVec 91k BSTR 약 2~3MB/열 (ContentVec와 동급, 유계 — 수용).

### 3.3 렌더 경로 (modColumnScan)

- 균일/혼합 블록: **블록별 Evaluate(TEXT) 1회** (혼합은 블록 수만큼 — 유계).
  General은 영문 "General" 매핑, `!` 제거, `*` 패딩은 접힌형 cleanFmt 그대로 —
  전부 기존 WText 규칙 재사용. CF 열도 동일(P9: WText가 캐논형 오라클).
- 텍스트 셀/텍스트 열(`@`): 렌더 불요(키=CStr(Value2)), Evaluate 생략.
- 빈칸: IsEmpty(v2) 가드(렌더값 무시). 에러셀: 배열 원소 IsError -> 셀별 `.Text` 폴백.
- 병리적(분할예산 초과): 현행 BuildPerCell 폴백 유지.
- AutoFit 재독(#-런/General 잘림)은 **소멸** — Evaluate(TEXT)는 폭 무관(P7과 정합).

### 3.4 매칭 경로 (modMatch)

- 완전일치: 토큰들을 소형 dict로, RenderedVec 1패스 스캔 -> matched + 키별 행수.
- 값 브리지: TryParseValues -> 블록별 WText 후보키 -> 같은 패스에서 멤버십.
  (값쌍둥이는 블록별 서식이 각자 렌더하므로 FACT 3 의미론 유지.)
- 부분일치: InStr 직스캔(39ms) 또는 지연 Displays 구축 후 키 스캔 — 구현 단순한 쪽.
- 자가검증: 스캔이 계수를 냈으므로 ExpectedRows는 O(토큰수).

### 3.5 제외 모드 (modApply) — P10 게이트

- 토큰 <=2: `Criteria1:="<>"&t1 (Operator:=xlAnd, Criteria2:="<>"&t2)` 스칼라.
- 토큰 >=3 또는 P10 불통과: 현행 여집합 배열 폴백(지연 Displays 구축 + Difference).
  고카디널에서 4초는 **문서화된 한계**로 잔존 — 실사용 제외는 통상 1~2건.
- **P10 프로브(AutoFilterTest, 구현 전 필수)**: (a) `"<>"`가 표시 문자열 의미론인가
  (등호 스칼라는 확인됨, 부등호 미확인), (b) `"<>x"`가 빈칸을 표시하는가
  (현행 제외는 빈칸 포함 — 의미론 일치 확인), (c) 접힌형(회계)도 매칭하는가.

## 5. 스테이지 (각각 push -> test green -> commit)

- **Stage P10**: AutoFilterTest에 `"<>"` 스칼라 프로브 + findings 기록.
- **Stage A (가산)**: modColumnScan에 `RenderBlockBulk`(Evaluate 경로) 병존 신설 +
  Test_CS_BulkRenderEquiv (기존 경로와 전수 동치 단언). 기존 렌더 경로 무변경.
- **Stage B (자산)**: clsColAsset에 RenderedVec + 지연 인덱스 프로퍼티. BuildAssetFromSig가
  벌크 경로로 RenderedVec 생산. Displays/ValueMap/RowCountByKey 소비자는 무수정 동작
  (지연 구축이 투명). 스위트 green = 의미론 보존 증명.
- **Stage C (매칭 재배선)**: modMatch를 멤버십 스캔으로 전환(반환 계약 유지),
  modFilterRun 자가검증을 스캔 계수로. 홧 경로에서 지연 인덱스 미구축 확인
  (성능 단언: fixture 콜드 < 300ms를 modBenchReal로 수동 확인).
- **Stage D (제외 특례)**: P10 결과에 따라 `"<>"` 스칼라 + >=3토큰 폴백. 빈칸 의미론 테스트.
- **Stage E (정리/문서)**: 구 RenderBlock 고유값 렌더 경로 정리(병리적 폴백은 유지),
  src/CLAUDE.md 아키텍처 절 갱신, fixture 재벤치 수치 기록.

## 6. 리스크 / 한계

- Evaluate 동적배열 스필은 이 환경(M365)에서 실측 동작 확인됨. 구버전 Excel 배포
  대상이 생기면 재검(실패 시 배열 비반환 -> 현행 경로 자동 폴백 설계).

- 3+토큰 제외 & 고카디널 = 4초 잔존(문서화). 필요 시 후속(예: 헬퍼열)은 별도 설계.
- 행 스왑 등으로 지문 불일치 시 재스캔 1회는 현행과 동일(무해).
