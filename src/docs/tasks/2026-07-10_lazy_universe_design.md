## 2. 핵심 실측 — 재설계를 가능케 하는 사실

### 2.1 벌크 렌더: Evaluate(TEXT) COM 1회

`ws.Evaluate("TEXT(범위,서식)")`이 91,235행을 **1회 호출 113ms**로 렌더(배열 반환).
- 정합: 고유값 47,397 전수 + General(189) + 빈칸 2만 열에서 현행 엔진 산출물
  (우주+행수지도)과 **완전 동치, 불일치 0**.
- WText(=TEXT 함수) 단독 오라클도 전수 0 불일치 (uniq 47,397, `#,##0`/General).
- **함정(실측)**: `TEXT(빈칸)="0"` — v2 IsEmpty 가드로 빈칸을 렌더값과 무관하게
  건너뛰어야 한다. 에러셀은 에러가 전파되어 배열 원소가 Error — 셀별 `.Text` 폴백.

### 2.2 멤버십은 dict 없이 싸다

렌더 배열 직스캔(91,235행): 토큰 1개 StrComp **9.8ms**(+빈칸/행수 계수 공짜),
토큰 20개(소형 dict) 54.7ms, 값 브리지(파싱값 WText 1회 -> 스캔) 11.7ms.
부분일치 InStr 직스캔 39.1ms. **지연 uniq dict 구축(제외가 요구할 때 1회) 179.7ms.**

### 2.3 dict의 소비자 분석

| 자료구조 | 소비자 | 홧 경로(퀵/포함 완전일치)에 필요? |
|---|---|---|
| Displays(clsSet 우주) | 제외(universe-matched), 부분일치 | 불요 — 멤버십 스캔으로 대체 |
| ValueMap | 값 브리지 | 불요 — 파싱값 WText 1회 + 멤버십 |
| RowCountByKey | 자가검증 ExpectedRows뿐 | 불요 — 멤버십 스캔이 계수 반환 |

## 3. 설계

### 3.1 지배 원리 (재정식화)

```
우주      = 관측된 렌더 배열 (블록별 Evaluate(TEXT) 1회, 빈칸/에러 가드)
집합/지도 = 우주가 아니라 우주에 대한 '인덱스'.
            그것을 요구하는 소비자(제외/부분일치)가 처음 나타날 때 지연 구축,
            자산에 캐시. 홧 경로는 인덱스 없이 배열 직스캔.
matched   = 표시레인(토큰 멤버십 스캔) UNION 값레인(파싱값 -> 블록서식 WText -> 멤버십)
적용      = xlFilterValues(matched)                       [포함]
          = xlFilterValues(여집합 + "=")                  [제외, P10 불통과로 스칼라 드랍]
계수      = 멤버십 스캔의 부산물 (자가검증 ExpectedRows, BlankCount)
```

### 3.2 자산 구조 변화

- clsColAsset: `RenderedVec`(블록 렌더 완료된 표시키 배열, 행 정렬) 신설.
  `Displays`/`ValueMap`/`RowCountByKey`는 **지연 프로퍼티**로 강등(최초 접근 시
  RenderedVec에서 1회 구축 후 보관, 고카디널 ~180ms).
- 지문 계약(clsColSig/GetColumnAsset/Matches) 무변경. 캐시 적중 경로 무변경.
- 메모리: RenderedVec 91k BSTR 약 2~3MB/열 (ContentVec와 동급, 유계 — 수용).

### 3.3 렌더 경로 (modColumnScan)

- 균일/혼합 블록: **블록별 Evaluate(TEXT) 1회** (혼합은 블록 수만큼 — 유계).
  General은 영문 "General" 매핑, `!` 제거, `*` 패딩은 접힌형 cleanFmt 그대로 —
  전부 기존 WText 규칙 재사용. CF 열도 동일(P9: WText가 캐논형 오라클).
- 텍스트 셀/텍스트 열(`@`): 렌더 불요(키=CStr(Value2)), Evaluate 생략.
- 빈칸: IsEmpty(v2) 가드(렌더값 무시). 에러셀: 배열 원소 IsError -> 셀별 `.Text` 폴백.
- 병리적(분할예산 초과): 현행 BuildPerCell 폴백 유지.
- AutoFit 재독(#-런/General 잘림)은 **소멸** — Evaluate(TEXT)는 폭 무관(P7과 정합).

### 3.4 매칭 경로 (modMatch)

- 완전일치: 토큰들을 소형 dict로, RenderedVec 1패스 스캔 -> matched + 키별 행수.
- 값 브리지: TryParseValues -> 블록별 WText 후보키 -> 같은 패스에서 멤버십.
  (값쌍둥이는 블록별 서식이 각자 렌더하므로 FACT 3 의미론 유지.)
- 부분일치: InStr 직스캔(39ms) 또는 지연 Displays 구축 후 키 스캔 — 구현 단순한 쪽.
- 자가검증: 스캔이 계수를 냈으므로 ExpectedRows는 O(토큰수).

### 3.5 제외 모드 (modApply) — P10 게이트 **[개정 2026-07-10: 불통과, 특례 드랍]**

P10 프로브 실측(AutoFilterTest `RunP10Only`, gap-probe-findings.md P10 절):
- (a) **실패** — 부등호 스칼라는 표시 의미론이 아니라 **값 강제**: `<>1,234,567`이
  숫자 셀만 숨기고 표시쌍둥이 텍스트는 잔존(과소 제외), `<>0.5`가 표시 "0.50" 셀을
  숨김(과잉 제외). 등호/배열의 표시 문자열 의미론과 다른 축.
- (b) 통과 — `"<>x"`는 빈칸을 표시(현행 제외의 빈칸 포함과 일치).
- (c) **실패** — 회계 접힌형/패딩형 모두 `"<>"`에서 매칭 불가(제외가 아예 안 걸림).

**결정: 스칼라 특례 채택 불가(정합성 원칙).** 제외는 전 토큰수에서 현행 여집합 배열
(지연 Displays 구축 + Difference + `"="` 빈칸 항목) 유지. 고카디널 여집합 47k = 4초는
**문서화된 한계**로 잔존 — 후속 필요 시 별도 설계(예: 헬퍼열), 이 재설계 범위 밖.
