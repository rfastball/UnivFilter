## P15 (AutoFilterTest) - "<>" 스칼라 재실험: 텍스트 열 한정

P10(숫자 혼합 열)을 버그2 상황(255자 초과 값이 사는 텍스트 열)으로 좁혀 재실험.
데이터 17행: 300자 텍스트 2종, a/A/b, 와일드카드 문자 텍스트(a*b, a?c, a~b, axb),
텍스트 "123"과 숫자 123, 텍스트 "5 kg"과 숫자 5(`0" kg"`), 텍스트 "ID-abc"와
"abc"(`"ID-"@`), "a "(끝 공백), 빈칸.

| criteria | 숨은 셀 | 판정 |
|---|---|---|
| `<>a` | a, A, "a " | 대소문자 무시, **끝 공백 무시**, 빈칸 가시 |
| `<>` + 300자 | 해당 긴 값만 | 긴 값 스칼라 가능 |
| `<>a` AND `<>b` / `<>`300자 AND `<>a` | 둘 다 | 2토큰 xlAnd 성립 |
| `<>a*b`, `<>a?b` | a*b, a~b, axb | **와일드카드 해석** |
| `<>a~*b`, `<>a~?c` | 해당 리터럴만 | `~*` `~?` 이스케이프 유효 |
| `<>a~~b` | 없음 | `~~`는 이스케이프로 동작 안 함 (`~` 단독은 리터럴) |
| `<>123` | 숫자 123만 (텍스트 "123" 잔존) | **값 강제** (P10과 동일) |
| `<>5 kg` | 텍스트 "5 kg"만 (숫자 표시 "5 kg" 잔존) | 표시 의미론 아님 |
| `<>ID-abc` / `<>abc` | 텍스트 쌍둥이만 / `"ID-"@` 셀 | 텍스트섹션 셀은 **값으로** 비교 |

결론:
- `<>`는 "텍스트 셀 + 텍스트 섹션 없는 서식 + 숫자/날짜로 읽히지 않는 키"에서만
  표시 의미론과 일치한다. 그 조건을 자산(ContentVec/RenderedVec/블록 서식)에서 확인할 수
  있으므로, 버그2를 **조건부 `<>` 경로(제외 키 <=2, 와일드카드 이스케이프) + 그 외 거부**로
  처리할 근거가 생겼다. 일반 제외 수단으로는 여전히 불가(P10 결론 유지).

### P15 부수 발견 - 신규 결함 2건

| criteria | 표시된 셀 | 영향 |
|---|---|---|
| `arr["a*b"]`, `arr["a?b"]`, `="a*b"` | a*b, a~b, axb | **배열/등호도 와일드카드 해석** |
| `arr["a~*b"]`, `arr["a~?c"]`, `="a~*b"` | 해당 리터럴만 | 이스케이프로 해결 가능 |
| `arr["a"]`, `arr["a "]`, `="a"` | a, A, "a " | **끝 공백 차이는 같은 키** |

  | criteria | 표시 | 규칙 |
  |---|---|---|
  | `arr["a~b"]`, `="a~b"` / `arr["a~~b"]` | a~b / 0건 | 와일드카드 없으면 `~`는 리터럴 |
  | `arr["a~~*b"]` / `arr["a~~~*b"]` | a~b, a~*b, a~xb / a~*b | 패턴 모드에서 `~~`=`~`, `~*`=`*` |
  | `arr["a~*b","a~b"]` | a*b, a~b | 2항목 배열은 항목별 판정 |
  | `arr["a*b","zz1"]` / `arr["a*b","="]` | 와일드카드 4행 | **2항목 이하 = 패턴** |
  | `arr["a*b","zz1","zz2"]` / `arr["a~*b","zz1","zz2"]` | a*b / **0건** | **3항목 이상 = 리터럴 값 목록** |

  `~`를 무조건 이스케이프해 "와일드카드 없는 `~` 포함 긴 값"이 0건이던 잠복 결함도 함께
  수정. 회귀 소유자 `Test_AP_WildcardLiteral`, 전체 70/70 green.
  실사용 영향: 퀵 필터 1토큰(1항목 배열)처럼 가장 흔한 경로가 해당됐다.
- 버그4(끝 공백): AutoFilter는 "a"와 "a "를 같은 값으로 본다. UnivFilter 키는 둘을 구분해

## P14 (AutoFilterTest) - 표식 선행 렌더 (버그1 설계 게이트)

표식 M = ChrW(&HE000)을 텍스트 앞에 붙여 `TEXT(M & 값, 서식)` 후 M 제거. 서식 12종 x 값 5종
("abc", "123", "2024-01-03", "해당없음", 300자) + AutoFilter 매칭(1항목 패턴 / 3항목 값목록 동일 결과).

| 서식 | 표식 렌더 = .Text | AutoFilter가 매칭하는 키 | 비고 |
|---|---|---|---|
| `"ID-"@`, `0;-0;0;"["@"]"`, `@" / "@`, `;;;` | 일치 | 표시 문자열 ("ID-123", "ID-2024-01-03" 포함) | **숫자형 텍스트 강제 변환 소멸**, 원문 "123"은 0건 |
| 회계 `..;_-@_-` / `@_)` | 일치 (" 해당없음 ", "abc ") | 원문/표시/트림 모두 | 여백 공백은 매칭에서 무시 |
| `@*-` (채움) | 불일치 (.Text는 대시 채움) | 원문=표식 렌더 "abd" | **.Text는 틀린 키**, TEXT는 채움 문자를 버려 정답 |
| `"Hi!"@` | 불일치 ("Hiabf") | .Text "Hi!abf" | 기존 `!` 일괄 제거 탓 |
| `[Red]@` (로컬 `[빨강]@`) | TEXT 오류 | .Text "abg" | 로컬 색 이름은 TEXT 미해석 |
| `@`, `General`, `#,##0` | 일치, 빠른 판정 통과 | - | 텍스트 섹션 없음 |
| 모든 서식 + 300자 텍스트 | TEXT 오류(단건/벌크 원소) | `="ID-"&300자`, `=`300자 **모두 0건** | 기존부터 매칭 불가 |

- 벌크 `Application.Text(표식 배열, 서식)` 결과는 단건과 전부 동일, 300자 원소만 원소 단위 오류.
- 빠른 판정 `TEXT(M&"x", 서식) = M&"x"`: 텍스트 섹션 없는 서식과 `@*-`(채움은 결과에서 사라짐)만 통과.
- P14b: 같은 서식을 **영문 `NumberFormat`(! 미제거)**으로 렌더하면 `[Red]@`, `[색10]@`,
  `#,##0;[Red]-#,##0`, `[Blue]General`, `"Hi!"@`, `@!)`(로컬 `@!!)`) 8종 모두 .Text와 일치하고
  빠른 판정도 정확하다. 로컬 서식은 색 이름에서 오류, `!` 제거는 리터럴 `!`를 잃는다.

## P16 (AutoFilterTest) - 공백

| 데이터 / criteria | 결과 |
|---|---|
| "a", "a ", " a", "a  ", " a " | 배열(1항목/3항목) `a`, `a `, ` a`, ` a ` 어느 것이든 5행 모두 |
| `=a` / `= a` (스칼라) | 5행 / **0건** (스칼라 criteria의 앞 공백은 매칭을 깬다) |
| 전각 공백(U+3000) 앞/뒤, NBSP(U+00A0) 뒤 | 자기 자신만 (무시 안 됨) |
| "a b" / "a  b" | 서로 구분 (내부 공백 접힘 없음) |
| 숫자 1234: `#,##0_)` ("1,234 ") / `#,##0` | `1,234`, `1,234 ` 모두 두 셀 매칭 |

결론: AutoFilter는 **앞뒤 ASCII 공백(U+0020)만** 무시한다 = VBA `Trim$`과 같은 집합.
UnivFilter 입력 토큰은 이미 `Trim$`(modInputParse)이므로 공백이 붙은 키는 입력으로 도달할 수 없다.

### P16b - 빈칸 유사 셀, 탭/줄바꿈

## P17/P17b (AutoFilterTest) - 숫자 렌더 서식 (이슈 #1)

후보: 현행 `TEXT(값, 로컬 서식에서 ! 제거)` / 영문 `NumberFormat` / 로컬 + 토큰 치환. 판정은 AutoFilter 3항목 배열 매칭.

| 서식 (영문 -> 로컬) | 현행 | 영문 | 로컬+치환 |
|---|---|---|---|
| `0\0` -> `0!0` (화면 120) | **12 (조용히 틀림)** | 120 | 120 |
| `0\!` -> `0!!`, `0"!"` | 1234 (0건) | 1234! | 1234! |
| `0\ \k\g` -> `0 k!g`, `0\"` -> `0!"` | TEXT 오류 | 정답 | 정답 |
| 색 9종 `[Red]`->`[빨강]`, `[Cyan]`->`[녹청]`, `[Color1]`->`[색1]` 등 | TEXT 오류 (셀별 .Text 폴백) | 정답 | 정답 (색 이름 치환) |
| `[DBNum1]General` -> `[DBNum1]G/표준`, `[Blue]General;[Red]-General` | `/표준`, 오류 | 정답 | 정답 (General 치환) |
| 내장 `m/d/yyyy`(ID 14) -> `yyyy-mm-dd`, ID 22 | 정답 | **`1/3/2024` (0건)** | 정답 |
| 내장 통화 `$#,##0_);($#,##0)` -> 원화 `#,##0;-#,##0`, 회계 ID 42/44 | 정답 | **`($1,234)` (0건)** | 정답 |
| 날짜 로컬 토큰(`aaa`, `[$-412]AM/PM`), `%`, 분수, 지수, `[h]:mm`, `"원"` | 정답 | 정답 | 정답 |

- 이슈 원안(영문 서식)은 **기각**: 내장 로캘 서식은 영문 문자열이 미국식 정의라 TEXT가 미국식으로 렌더한다.
  짧은 날짜(ID 14)는 국내에서 가장 흔한 날짜 서식이다. 텍스트 섹션 경로도 같은 이유로 영문 서식을 버렸다.
- 수정: `modColumnScan.NormFmt` = 로컬 서식에서 따옴표 밖 이스케이프 `!c` -> `"c"`, 로컬 색 이름 9종 -> 영문,
  `G/표준` -> `General`. 숫자/텍스트 섹션/값 레인 후보키 모두 같은 서식. 회귀 소유자 `Test_CS_NumFmtNormalize`.
